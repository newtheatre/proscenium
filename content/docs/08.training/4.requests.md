A member who wants a module that has no session can request it from the catalogue. The
requests gather on the demand board at **Manage, Training, Requests**, so whoever can run a
session sees what is wanted. Anybody who can read the catalogue can open it; a department
lead sees requests for their own departments' modules only. Answering one needs
`training.write` or a lead's standing in the module's department.

::callout{icon="i-lucide-info" color="info"}
A request is a demand signal, never a queue position. It confers no priority or place in any
session, and nothing here resolves on a timer: an ask nobody acts on keeps showing up, which
is the point of it.
::

## Reading the board

![The demand board with a module's card (1), the count waiting (2) and a requester's Answer button (3)](/images/docs/training/requests.png)

1. Each card is one module, busiest first, with its id, title and department.
2. The badge counts how many people are **waiting** on it.
3. Under each module the requesters are listed with the note they wrote, and an **Answer**
   button beside each.

The board shows the busiest modules; answer or schedule some of these to see the rest. When
nothing is outstanding the screen says so.

## Answering a request

Answering is a reply, not a verdict. The requester is shown what you write, so tell them
where it stands rather than only that it is declined.

1. Press **Answer** beside the person.
2. Write **What to tell them**: "Not running this term, but it is on the list for next", for
   example. Nothing sends until you do, and a reply needs a few words at least.
3. Press **Send reply**.

The request is marked answered and drops off the board. The person sees your words against
their request on their own training page.

## Scheduling instead

The better answer to a busy card is usually a session. When a session is scheduled and opened
for sign-up at once, every open request for a module it teaches is resolved and each requester
is emailed once, so they can sign up. See [Sessions](/docs/training/sessions).

## If something goes wrong

- **"That request has already been answered"**: somebody else got there first, or the member
  withdrew it. Reload the board.
- **"That request is no longer here."**: the request no longer exists. Reload.
- **"You do not have permission to do that"**: a lead is answering a request on a module
  outside their own departments.
- **"The board could not be read"**: the list failed to load, which is not the same as nothing
  being asked for. Reload, and if it keeps happening say so.

## What happens next

An answer is in the audit trail with the actor and the module; the words you wrote are shown
to the requester and kept off the trail. A resolved request, whether answered or met by a
session, frees the member to ask again later.
