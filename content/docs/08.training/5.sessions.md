A session is one dated delivery of one or more modules, with a trainer, a room's worth of
places and a register. The sessions screen is at **Manage, Training, Sessions**, and opens for
the Training Manager, the Manager and every current **trainer**: somebody holding a current
record on a module that grants trainer standing. There is no trainer role; the standing goes
the moment that record lapses or is revoked.

::callout{icon="i-lucide-info" color="info"}
**Teaching is planned, and running one is earned.** A trainer may schedule only modules they
currently hold. A certification is not taught by session at all: it is signed off on
experience gained outside training, on the [Records](/docs/training/records) screen.
::

## If something goes wrong

- **"Running a session needs a current trainer certification"**: your trainer standing has
  lapsed, or you never had it. A lead of the certification's department can sign it off.
- **"A session is scheduled for a future day; logging one already delivered is a different
  act"**: the day chosen has passed. Use **Log a session**.
- **"You do not yet hold ..., which this session needs first"**: a module chosen is not one you
  currently hold, so you cannot teach it.
- **"... cannot be taught at a session"**: the module is a draft, retired, or awarded by
  sign-off.
- **"That session is on ... Its register opens on the day, not before"**: wait for the day.
- **"That session was cancelled, so its register can never be opened"**: schedule a new one.
- **"That register has been opened, so correct the session rather than cancelling it"**: use
  the edit window.
- **"This session is past taking sign-ups, so its capacity no longer decides anything"**: the
  register was opened or the session cancelled while you were changing the places. Reload; the
  register is where the room is counted from now on.
- **"That session changed while you were editing it, so open it again"**: somebody else
  changed its places first, and yours were not saved. Reload, check the places and set them again.
- **"This is somebody else's session to change"**: you are not running it, and only its trainer,
  the Training Manager and the Manager change its places.
- **"The register is open, so what this session teaches is frozen. Release it deliberately to
  change it"**: tick **Release the freeze** and save again, if you mean to.
- **"This register has been marked, so its records are the correction path now"**: what the
  session taught is settled by its records. Correct a record instead.
- **"The register has to be covered exactly. ..."**: the marks do not match the list, which
  happens when somebody was added on another device. Reload and mark again.
- **"Nobody is marked present. If that is right, confirm it and the session will award
  nothing"**: press submit again to confirm.
- **"This register has already been marked. Correcting it is the edit window, not a second
  mark"**: somebody else submitted first, or you are on a stale page. Reload.
- **"Somebody marked this register while you were marking it, and theirs landed first"**: two
  devices submitted at once. Reload and check the result before doing anything else.
- **"That session was held more than ... days ago. Correcting it now is the IT Manager
  revoking the record and granting it again"**: the edit window has closed.
- **"This session is safety critical, so it needs ... first"**: the walk-in lacks a
  prerequisite that cannot be waived.
- **"They do not hold ... Confirm that and they can be added"**: press **Add them anyway** if
  you know why.
- **"Nothing can be delivered to that address"** or **"That account has been erased, so nothing
  can be recorded against it"**: the address given cannot take an account.
- **"That address is waiting to be linked to ...'s account"**: an existing account takes that
  theatre address at its first Google sign-in. Find that person by name instead.
- **"You confirmed n records and this would now create m. Please preview it again."**: the
  plan changed between the preview and the log, most likely somebody awarded the module in
  between.
- **"Only the trainer running this session may ..."**: the session belongs to somebody else and
  you are neither the Training Manager nor the Manager.
- **"The sessions could not be read."** or **"The register could not be read"**: the list
  failed to load, which is not the same as nobody being on it. Reload before you act.

## The list

![The sessions list with the search field (1), the Filters button, where the mine-only switch lives (2), the Schedule a session button (3), the Log a session button (4), the table (5) and a row's open arrow (6)](/images/docs/training/sessions.png)

1. **Search** by a date, a place, a trainer or a module id.
2. **Only sessions I am running** hides everybody else's.
3. **Schedule a session** and 4. **Log a session** open the two forms below.
5. Each row shows when, what it teaches with the trainer and the place, how many places it
   holds, and its status: **Planned** (not yet open for sign-up), **Open for sign-up**,
   **Full**, **Delivered** or **Cancelled**. Sessions are listed soonest first.
6. The arrow opens the session's own page.

## Scheduling a session

Arriving from **Schedule a session** on the [demand board](/docs/training/requests) opens this
form with that module already chosen, so only the day, the times and the places are left.

1. Press **Schedule a session**.
2. Choose the **Day**. It has to be in the future; teaching that already happened is logged,
   not scheduled.
3. Set **Starts** and **Ends**, London wall clock, and optionally **Where**.
4. Set **Places**. The screen names the smallest and largest room it accepts.
5. Choose **What it teaches**. Only active modules that are not awarded by sign-off are
   offered, and a trainer who is not the Training Manager or the Manager may pick only modules
   they currently hold.
6. Optionally write **What to expect**, which members see when deciding whether to come, and
   **Notes**, which only trainers and department leads see.
7. Under **Sign-up**, leave **Open for sign-up as soon as it is saved** on, or turn it off and
   give the day and time (London) it should open. A planned session is invisible to members
   until it opens.
8. Press **Schedule the session**.

![The scheduling form with the day (1), the start (2) and end (3) times, the place (4) and the number of places (5)](/images/docs/training/schedule-session.png)

A session opened for sign-up straight away resolves every open request for a module it
teaches, and each requester is emailed once. A session set to open later resolves nothing when
it is scheduled: it is invisible to members until a check that runs every ten minutes finds
that its time has come, opens it, and resolves those requests then. Expect it to open within
ten minutes of the time you named, not on the minute.

## Places and the waiting list

Sign-up never refuses for fullness. A member's place or waiting-list position is worked out
from the order people signed up in against the session's places, every time it is asked; no
waiting list is stored. Withdrawing and rejoining puts a member at the back.

Sign-up closes {{ SESSION_SIGNUP_CLOSES_HOURS }} hours before the session starts, when its day
arrives, or when the register opens, whichever is first. Withdrawing stays open while the
register is open. When a withdrawal or more places moves somebody on the list into a place,
they are emailed once. When fewer places moves somebody who had one back to the waiting list,
they are emailed once with their new number.

A member signing up for a safety-critical module without its prerequisites is refused with the
missing modules named; a gap in an ordinary module's prerequisites warns but allows.

## A session's page

Open a session from the list. The page shows its status, **Who is coming** with **Has a
place** or **Waiting, number n** against each name, **What it teaches** and the trainer's
notes, and a button to the register that says **Take the register**, **Carry on with the
register** or **See the register** depending on where the session has got to.

![A session's page with the status badge (1), the register button (2), the cancel button (3) and the list of who is coming (4)](/images/docs/training/session.png)

### Changing the places

Offered while the session is planned, open or full and its register has not been opened. Once
the register is open the room is counted rather than planned.

1. Press **Change the places** under **Who is coming**.
2. Set **Places**. Before you save, the form says how many people the change would move; each
   of them is emailed.
3. Press **Save the places**. The page then says how many were promoted and how many moved back
   to the waiting list.

Nobody is ever taken off the list. Raising the places gives them to the people waiting, in the
order they signed up. Lowering them moves whoever signed up last among those with a place back
to the waiting list, ahead of everybody already waiting: they keep their turn, and they are the
first to get a place if one comes up again.

### Changing what it teaches

Offered until the register is marked. The same rules as scheduling apply: only active modules
not awarded by sign-off, and only what you hold unless you are the Training Manager or the
Manager.

1. Press **Change the modules** under **What it teaches**.
2. Add or remove modules. As you choose, the form lists everybody signed up who lacks a
   prerequisite you are adding, with what they lack. This is a warning: saving does not take
   anybody off the list, so tell them before the day. A prerequisite the session already needed
   is not listed again; members were warned about it when they signed up.
3. If the register is already open, what the session teaches is frozen: marking the register
   awards exactly these modules. Tick **Release the freeze** to change it anyway. The release is
   written to the audit trail, and it cannot happen once the register has been marked.
4. Press **Save the modules**.

### Cancelling

1. Press **Cancel this session**. It is offered only before the register opens: after that the
   session happened, and the edit window is how it is put right.
2. Say **Why it is off**. Everybody signed up is emailed this, so write it for them.
3. Press **Cancel the session and tell everybody**.

Everybody on the list, placed and waiting alike, is emailed once. A cancelled session awards
nothing and its register can never be opened. The trainer running the session cancels it, and
so do the Training Manager and the Manager.

## Logging a session already taught

Teaching that happened away from a screen, a workshop run on paper for instance, is logged
after the fact. Nothing is written until you have seen exactly what it would create.

1. Press **Log a session**.
2. Choose **The day it was taught**, a past day read in London time.
3. Choose **What was taught**. The same rule as scheduling applies: active modules not
   awarded by sign-off, and only what you hold unless you are the Training Manager or the
   Manager.
4. Add **Who was there**, one at a time, from the person search. For somebody who has never
   signed in, press **By address** and give their email address and, if you know it, their
   name: they get an account they can claim later, and the training waits on it.
5. Press **Preview the records**. The preview lists one record per person per module,
   dated to the day it was taught, with the date each would run to; anybody who already holds
   the module from that day is marked **Already recorded** and not written again.
6. Where somebody lacks a prerequisite for an ordinary module, tick the line to confirm you
   know. A missing prerequisite for a safety-critical module blocks the log outright.
7. Press **Log it**. The count you previewed is sent with it, and a log whose count has changed
   since is refused rather than guessed.

## The register

The register is the single act that awards a record for a taught session. It lives at
`/training/sessions/<id>/register`, is built for a phone in one hand on a door, and is reached
by the register button on the session's page. The trainer running the session opens and marks
it, and so do the Training Manager and the Manager.

### Opening it

1. On the day, press **Open the register**. Before the day the button is disabled and names
   the date; the server refuses it too.
2. Opening closes sign-up and freezes what the session teaches.

### Marking it

1. Everybody starts absent. Press a name to mark them present; press again to undo. A name marked
   **Waiting** was only ever on the waiting list, and a **Walk-in** was added on the door.
2. To add somebody who turned up unannounced, press **Add someone**. Pick them under
   **Somebody already known**, or give their email address and name to make them an account
   they can claim later. Somebody missing a prerequisite for an ordinary module is shown what
   they lack and can be added with **Add them anyway**; a gap in a safety-critical module's
   prerequisites cannot be waved through. Whoever you add is marked present, which is what
   adding them means.
3. Read the count under the list. Everybody left unmarked is emailed to say we missed them and
   gets no record.
4. Press **Submit**. If nobody is marked present the screen asks you to submit a second time:
   a session nobody came to is worth pausing over.

Marking creates one record per present person per module, dated to the day of the session
rather than the day it was marked. A register that stays unmarked is chased by email from
{{ REGISTER_NAG_START_DAY }} days after the session, every {{ REGISTER_NAG_CADENCE_DAYS }}
days, stopping after {{ REGISTER_NAG_STOP_DAYS }} days. The chasing is switched on in
[Settings](/docs/system/settings). Marking a stale register still awards.

### Correcting it

A mistake can be put right for {{ SESSION_EDIT_WINDOW_DAYS }} days after the session.

1. Open the register again and press **Correct it**. The marks come back as they were left.
2. Change what is wrong and press **Correct it: n present**.

What was awarded before is revoked and the corrected set is issued in its place, in one step,
so nobody is ever without a record they are about to get back. Somebody dropped by the
correction is emailed as an absentee. After the window closes, the only path is an
the IT Manager revoking the record on the [Records](/docs/training/records) screen and
signing it off again. Opening a settled register shows that it was marked and says so, with
nothing to mark, nobody to add and no submit button: those are the paths the server refuses,
so the screen does not offer them.

![A settled register on a phone, with the marked notice (1) and the line saying the records are settled (2)](/images/docs/training/register.png)

## What happens next

Scheduling, cancelling, opening the register, marking it, correcting it, adding a walk-in and
logging a delivery are each in the audit trail with the actor and the session; the cancellation
reason and any names stay off it. A marked register writes one record per present person per
module, which every gate reads at once; absentees are emailed once, and so is everybody on a
cancelled session. Members see their new record on their own training page.
