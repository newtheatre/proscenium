A shift template is how a venue is staffed: how many duty manager, door and bar shifts every
performance there needs. It is at **Manage, Rota, Shift templates**, and the Front of House
Manager reads the templates and changes them. The **Ready for a show night** card at the top of
the screen says what each role and each venue still needs before a volunteer can take a shift.

This is the first of the rota's four screens, which run in order: shift templates, the rota board,
bar openings, then approvals. **Fill the rota** at the top of this screen is the way on to the
next one.

::callout{icon="i-lucide-info" color="info"}
**A template reaches a performance only by stamping.** Adding a performance stamps its venue's
template straight away, and saving a template stamps every performance at that venue from tonight
onwards that has no shifts (a cancelled one does not count), so a venue's first template reaches
the diary already there.
Editing a template afterwards changes nothing already stamped: press **Stamp the diary** to carry
the change onto performances that already have a rota. A bar opening
that needs a different count for one evening is changed on [Bar openings](/docs/rota/bar-openings)
instead, and the template stays as it is.
::

## If something goes wrong

- **"A venue template needs one duty manager slot: the night cannot legally run without one"**:
  the duty manager count is 0. Set it to one.
- **"A venue template holds exactly one duty manager slot"**: the count is more than one. Only one
  duty manager shift exists per performance.
- **"A template names each role once"**: two rows for one role reached the server, which the dialogue
  itself cannot produce. Reload the page and try again.
- **"A shift starts and ends within eight hours of its performance"**: one of the timing fields is
  too large. A shift is worked around its performance, so the offsets are minutes, not hours of
  slack; leave the field blank to take the house default.
- **"This venue has no template, so there is nothing to stamp"**: the venue's template was removed
  between the page loading and the button being pressed. Reload.
- **"That venue is no longer here."**: the venue has been removed since the page loaded.
- **"… is an external venue, so it has no shift template: add its shifts on the rota board"**: the
  venue was marked external on **Venues** since the page loaded. Reload, and see
  **Staffing an external venue** below.

## Setting up a venue's staffing

The table lists every one of our own venues, with or without a template. A venue with none reads
"Nothing, so its performances show as unstaffed", and that is a visible gap rather than a quiet
one: it appears in the seven-day digest as soon as a performance there is inside the window.
An external venue is not listed, since it is staffed by hand (see below). A retired venue takes
no new performances, so it is listed only while it still holds a template: it is marked
**Retired** and carries **Remove** alone, so the template can be cleared and the venue deleted.

![The shift templates screen with the Ready for a show night card (1), the search (2), the venue table (3) and a venue's Set up the template or Edit button (4)](/images/docs/rota/templates.png)

1. **Ready for a show night** is covered below.
2. **Search** by venue name, or filter to venues that are staffed or not yet staffed.
3. **The table** shows what every performance at each venue is staffed with, as one badge per role.
4. Press **Set up the template** on a venue with no template, or **Edit** on one that has one.

The staffing dialogue asks for a count per role.

![The staffing dialogue with the duty manager count (1), the door count (2), the bar count (3), a role's timing fields (4) and Save the template (5)](/images/docs/rota/template-edit.png)

1. **Duty manager** is always exactly one. The night cannot legally run without one, and the
   database refuses a template that says otherwise.
2. **Door** is how many door shifts each performance needs. A 0 means the venue does not
   staff that role at all, and the role is left out rather than saved.
3. **Bar** works the same way.
4. **Starts before doors** and **Ends after the show**, in minutes, say when that role is worked.
   They are covered in the next section.
5. The dialogue counts the shifts every performance will carry, then **Save the template** keeps it.

Saving stamps the template onto every performance at that venue from tonight onwards that has no
shifts (a cancelled one does not count), and says how many shifts it added. A performance that
already has a rota keeps it: **Stamp the diary**, below, fills any slot it is missing, as the
message after saving says.

## When each role is worked

Under each role's count are two fields, **Starts before doors** and **Ends after the show**, both
in minutes. They say when that role's shift is worked: the bar usually opens before the door does
and closes after the audience has gone, and the duty manager is there for all of it.

Leave a field blank and the shift takes the house default: a shift starts
{{ SHIFT_START_BEFORE_DOORS_MINUTES }} before the doors open and ends
{{ SHIFT_END_AFTER_CURTAIN_DOWN_MINUTES }} after curtain down, both set by the IT Manager on
**Settings**.
Blank is the honest answer for a venue nobody has thought about yet, and it is what every venue
holds until somebody fills it in.

The end is counted from when the performance actually finishes, which is its curtain plus its
running time plus its intervals. Where the diary records no doors time or no running time, the
curtain stands in for it, so the window is the curtain plus the offsets and no wider. A performance
at a venue we run cannot be saved without its running time, so only one imported from the old
system, or one at a venue that has since become ours, can lack it; [Shows](/docs/box-office/shows)
names every show that still has one.

::callout{icon="i-lucide-info" color="info"}
**Times are stamped onto the shift, not read from the template.** A shift keeps the window it was
stamped with, so changing these fields changes nothing already in the diary: the new figures apply
to slots stamped from then on. **Stamp the diary** fills in the window of any shift that has none,
but it never rewrites one a shift already carries. Moving a performance's own curtain, doors time
or running time does move its shifts' windows: the shift is worked around the show.
::

The window is what a shift holder's authority runs on: the till, the door screen and the duty
manager's approvals open inside their own shift's window, with {{ SHIFT_AUTHORITY_GRACE_MINUTES }}
of grace either side, which the IT Manager sets on **Settings**. Somebody who arrives well before their
shift is told when it opens rather than told they have no shift.

## Stamping the diary

**Stamp the diary** adds every slot the template asks for to every performance at that venue from
tonight onwards that is missing one. Tonight starts at 04:00, so a night already under way is still
inside the window. Running it twice adds nothing the second time: a slot is identified by its role
and which one of that role it is, so filling the rota can only fill a gap and never make a
second shift where one already stands. The
screen reports how many shifts it added, or "Nothing to add" when every performance already has
its slots.

## Removing a template

**Remove** takes the template away, asking first: press **Remove the Main House template** in the
dialogue, or **Back**. Performances added at that venue from then on stamp nothing, and shifts
already in the diary are untouched. The button appears only on a venue that has a template to
remove.

## Staffing an external venue

A venue marked **External venue** on [Venues](/docs/box-office/venues) is somebody else's
building, and how many of us it needs changes from one hire to the next. It has no shift template:
marking a venue external removes the template it had, which the audit trail shows as **Shift
template removed**, it is left off this screen, and a performance there is added with no shifts at
all. A bar opening cannot be planned there either, since there is no bar count to staff it from.

Staff each of its performances by hand instead:

1. Open the **Rota board** at the night of the performance.
2. On the performance's card, press **Add a shift** once for each shift the hire needs. Start with
   the duty manager, slot 1: the night cannot legally run without one.
3. Name a person to confirm the shift at once, or leave it open for an eligible member to claim.

**Adding a one-off shift** on the [Rota board](/docs/rota/rota-board) page covers the dialogue.
Until its shifts are added, the performance appears in the morning digest as having none, which is
the reminder to do it.

## Ready for a show night

The card at the top of the screen gathers what a show night needs from four set-up screens, so
the Front of House Manager can see at a glance what is still missing. It has three parts.

**Who can claim each role** gives one line per role, duty manager, door and bar, naming the
training module a member must hold to take it. A role reads **Open** when its module is published
in the catalogue, and **Closed** otherwise, with the reason:

- "No module named yet": nobody can claim that role until one is named.
- "… is still a draft": the module exists but nobody holds it, so nobody can claim the role. Ask
  the Training Manager to publish it.
- "… is retired": nobody new can gain it. Name a current module instead.
- "Names …, which is not in the catalogue": the setting names a module id nobody has added.

The roles ship gated on the modules the committee named: duty manager on **Committee Operations
and Governance**, so it is held by committee members only; door on **Box Office and Ticketing**;
bar on **Selling Alcohol**. The IT Manager sees a field beside each line listing every module by
id and name; choosing one saves it at once, and clearing it sets the role to nothing. Everybody
else reads the lines and changes nothing.

::callout{icon="i-lucide-triangle-alert" color="warning"}
**A closed role is locked to everybody, not open to everybody.** The rota refuses eligibility it
cannot check rather than granting it, so until its module is published nobody can claim or be
assigned that role. The IT Manager also sees the same line on the site's health check.
::

**Each venue we run** gives one entry per venue that is not external or retired, marked **Ready**
once all three of these hold, and **Not ready** until then:

- its template, as the number of shifts on every performance, or "No template";
- its post-show checklist, which needs both system checks, **Unpaid holds released** and
  **Tonight's incidents reviewed**; a missing one is named, and the line opens
  [Checklists](/docs/rota/checklists);
- its emergency card, filed once its latest version carries an address; the line opens
  [Emergency cards](/docs/rota/emergency-cards).

The last line counts the preset calls and milestones on the
[Backstage board](/docs/rota/backstage-board). Every venue we run was given both system checks,
and the board its four routine calls (Standby, Hold, Clear and Ambulance), when this card was
added, so a new venue is the usual reason a line reads as missing.

A locked shift on a member's My rota names the module that would unlock it and links to the
catalogue. A role that is closed for everybody names the Front of House Manager as the person to
ask instead. The same check runs live, against the member's current training records, when they
claim and when an officer assigns them.

## What happens next

The audit trail shows a save as **Shift template set up** or **Shift template changed**, with
the slots before and after; a removal shows as **Shift template removed** with the slots it held,
and with the reason "external" when marking the venue external removed it.
Filling the rota adds one open shift per missing slot and shows as **Shifts stamped onto
performances**, naming the venue and the night it began at. New shifts are open, name nobody, and
appear on every eligible member's My rota at once. An eligibility change is a change to a setting
and is recorded as one.
