A shift template is how a venue is staffed: how many duty manager, door and bar shifts every
performance there needs. It is at **Manage, Tonight, Shift templates**. Seeing the templates needs
the `rota.read` permission and changing them needs `rota.write`; the Front of house manager role
holds both. The **Shift eligibility** card at the top of the screen is configuration rather than
rota data, so it shows only to somebody who also holds `config.read`, which in practice means an
administrator.

::callout{icon="i-lucide-info" color="info"}
**A template reaches a performance only by stamping.** Adding a performance stamps its venue's
template straight away. Editing a template afterwards changes nothing already in the diary: press
**Stamp the diary** to carry the change onto performances that already exist.
::

## Setting up a venue's staffing

The table lists every venue, with or without a template. A venue with none reads "Nothing, so its
performances show as unstaffed", and that is a visible gap rather than a quiet one: it appears in
the seven-day digest as soon as a performance there is inside the window.

![The shift templates screen with the shift eligibility card (1), the search (2), the venue table (3) and a venue's Set it up or Edit button (4)](/images/docs/rota/templates.png)

1. **Shift eligibility**, shown to administrators only, is covered below.
2. **Search** by venue name, or filter to venues that are staffed or not yet staffed.
3. **The table** shows what every performance at each venue is staffed with, as one badge per role.
4. Press **Set it up** on a venue with no template, or **Edit** on one that has one.

The staffing dialog asks for a count per role.

![The staffing dialog with the duty manager count (1), the door count (2), the bar count (3), a role's timing fields (4) and Save it (5)](/images/docs/rota/template-edit.png)

1. **Duty manager** is always exactly one. The night cannot legally run without one, and the
   database refuses a template that says otherwise.
2. **Door** is how many door shifts each performance needs. A nought means the venue does not
   staff that role at all, and the role is left out rather than saved.
3. **Bar** works the same way.
4. **Starts before doors** and **Ends after the show**, in minutes, say when that role is worked.
   They are covered in the next section.
5. The dialog counts the shifts every performance will carry, then **Save it** writes the template.

Saving tells you that performances added from now on are staffed from it. It does not touch
performances already in the diary.

## When each role is worked

Under each role's count are two fields, **Starts before doors** and **Ends after the show**, both
in minutes. They say when that role's shift is worked: the bar usually opens before the door does
and closes after the audience has gone, and the duty manager is there for all of it.

Leave a field blank and the shift takes the house default, which an administrator sets in
**Settings** as `SHIFT_START_BEFORE_DOORS_MINUTES` and `SHIFT_END_AFTER_CURTAIN_DOWN_MINUTES`.
Blank is the honest answer for a venue nobody has thought about yet, and it is what every venue
holds until somebody fills it in.

The end is counted from when the performance actually finishes, which is its curtain plus its
running time plus its intervals. Where the diary records no doors time or no running time, the
curtain stands in for it, so the window is the curtain plus the offsets and no wider.

::callout{icon="i-lucide-info" color="info"}
**Times are stamped onto the shift, not read from the template.** A shift keeps the window it was
stamped with, so changing these fields changes nothing already in the diary: the new figures apply
to slots stamped from then on. **Stamp the diary** fills in the window of any shift that has none,
but it never rewrites one a shift already carries. Moving a performance's own curtain, doors time
or running time does move its shifts' windows, because the shift is worked around the show.
::

The window is what a shift holder's authority runs on: the till, the door screen and the duty
manager's approvals open inside their own shift's window, with a grace period either side that an
administrator sets as `SHIFT_AUTHORITY_GRACE_MINUTES`. Somebody who arrives well before their
shift is told when it opens rather than told they have no shift.

## Stamping the diary

**Stamp the diary** adds every slot the template asks for to every performance at that venue from
tonight onwards that is missing one. Tonight starts at 04:00, so a night already under way is still
inside the window. Running it twice adds nothing the second time: a slot is identified by its role
and its ordinal on the performance, so a stamp can only fill a gap, never duplicate a shift. The
screen reports how many shifts it added, or "Nothing to add" when every performance already has
its slots.

## Removing a template

**Remove** takes the template away. Performances added at that venue from then on stamp nothing,
and shifts already in the diary are untouched. The button appears only on a venue that has a
template to remove.

## Shift eligibility

Which training module a member must hold to take each role is committee configuration. The card
carries one field per role, listing every module in the catalogue by id and name; choosing one
saves it at once, and clearing it sets the role back to unset. A role with nothing chosen reads
"Closed: nobody can claim this role yet."

::callout{icon="i-lucide-triangle-alert" color="warning"}
**A role with no module set is locked to everybody, not open to everybody.** The rota refuses
eligibility it cannot check rather than granting it, so until a module is named nobody can claim
or be assigned that role. Name a module for each role before the first performance is stamped.
::

A locked shift on a member's My rota names the module that would unlock it and links to the
catalogue. The same check runs live, against the member's current training records, when they
claim and when an officer assigns them.

## If something goes wrong

- **"A venue template needs one duty manager slot: the night cannot legally run without one"**:
  the duty manager count is nought. Set it to one.
- **"A venue template holds exactly one duty manager slot"**: the count is more than one. Only one
  duty manager shift exists per performance.
- **"A template names each role once"**: two rows for one role reached the server, which the dialog
  itself cannot produce. Reload the page and try again.
- **"A shift starts and ends within eight hours of its performance"**: one of the timing fields is
  too large. A shift is worked around its performance, so the offsets are minutes, not hours of
  slack; leave the field blank to take the house default.
- **"This venue has no template, so there is nothing to stamp"**: the venue's template was removed
  between the page loading and the button being pressed. Reload.
- **"That venue is no longer here."**: the venue has been removed since the page loaded.

## What happens next

A saved template is audited with a from/to diff of its slots, as `shift-template.created` or
`shift-template.updated`; a removal is `shift-template.removed` with the slots it held. A stamp
writes one open shift per missing slot and one `shift.stamped` audit row naming the venue and the
night the window opened at. Newly stamped shifts are open, name nobody, and appear on every eligible
member's My rota at once. An eligibility change is a settings change, audited as one.
