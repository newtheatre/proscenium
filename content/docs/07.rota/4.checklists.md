Every venue has a checklist in two halves: what is ticked before the house opens, and what is
ticked before the night is closed. The duty manager works through it on the phone; this screen is
where the committee writes it. It is at **Manage, Rota, Checklists**, and the Front of House
Manager reads the lists and changes them.

::callout{icon="i-lucide-info" color="info"}
**Changes here apply from the next show night.** A night already touched keeps the checklist it
was stamped with, so editing an item at 19:00 changes nothing about tonight.
::

## If something goes wrong

- **"Give the item a label"**: the label is empty. The dialogue will not save without one.
- **"That checklist item is no longer here."**: the item was removed or belongs to a different venue than the page
  thinks. Reload.

## Adding an item

The table lists every venue and its current items, each with its phase, its label, whether it
ticks itself, and whether it is optional. An external venue is somebody else's building and is
staffed by hand, so it is listed only once one of its performances from tonight onwards has a shift
on the [Rota board](/docs/rota/rota-board), or while it already holds an item.

Every venue we run was given the two items that tick themselves when the readiness card was added;
a venue added since starts with neither, and the readiness card on
[Shift templates](/docs/rota/shift-templates) names the one it lacks. Add each with **How it
ticks** set to it.

![The checklists screen with the search (1), a venue's checklist (2) and its Add an item button (3)](/images/docs/rota/checklists.png)

1. **Search** by venue name, or filter to venues that are configured or not yet.
2. **Each row** is one venue, listing its items in order with **Edit** and **Retire** beside each.
3. **Add an item** opens the item dialogue for that venue.

![The item dialogue with the phase (1), the label (2), the order (3), how it ticks (4), the required switch (5) and Save the item (6)](/images/docs/rota/checklist-item.png)

1. **Phase** is **Pre-show** or **Post-show**.
2. **Label** is what the duty manager reads. Write it as an instruction: "Fire exits checked and
   unobstructed", not "Fire exits".
3. **Order** sorts the phase, lowest first.
4. **How it ticks** is **Hand-ticked** for most items. The two that tick themselves, **Unpaid
   holds released** and **Tonight's incidents reviewed**, read the night's data and cannot be
   ticked by hand; on a night one cannot clear, the duty manager makes it an exception with a
   reason. A paid booking nobody used never holds the first open: it is a no-show in the night
   report.
5. **Required** means the night cannot be closed until the item is ticked, or made an exception
   with a reason against it. An optional item is shown but never blocks.
6. **Save the item** adds it to the list.

## Editing and retiring

**Edit** changes any of the above for nights not yet stamped. **Retire** asks first, with
**Retire the item** in the dialogue, and then takes an item off the list from the next night; it is never deleted, so a night already checked off keeps referencing what it
was checking. A retired item stays on this screen, greyed and marked **Retired**, below the venue's
live items; **Reinstate** puts it back on the list from the next night.

## What happens next

Every add, edit, retirement and reinstatement is recorded. The audit trail reads **Checklist
item added** with the phase and the label, **Checklist item changed** with the label and the
required setting before and after, **Checklist item retired** and **Checklist item reinstated**.
On the night, an incomplete required
pre-show item shows as a warning on the duty manager's screen from house open, and every required
item made an exception prints in the night report with its reason.
